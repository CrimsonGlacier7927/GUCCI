# 3x-ui روی Railway با یک پورت واحد

این ریپازیتوری، 3x-ui (نسخه **v2.9.4**) رو به همراه یک nginx reverse proxy اجرا می‌کند که هم پنل وب، هم سرویس سابسکریپشن و هم اینباندهای VLESS/WebSocket را از طریق **یک پورت واحد** (همان پورتی که Railway اختصاص می‌دهد) در دسترس می‌گذارد — دقیقاً مثل معماری RVG.

## معماری و پورت‌های داخلی

| سرویس | پورت داخلی | مسیر عمومی |
|---|---|---|
| پنل 3x-ui | 2053 (پشت nginx) | فقط `https://دامنه/gucci/` — nginx روی **پورت 1** و 3000 گوش می‌دهد و پنل را سرو می‌کند |
| سرویس سابسکریپشن | 443 (فقط loopback، HTTP داخلی) | `https://دامنه/sub/...` — **خودکار با دامنه‌ای که پنل با آن باز می‌شود** |
| اینباند اصلی VLESS/WS | 8080 | `https://دامنه/هرمسیر` |
| اینباندهای اضافی | 8081 تا 8100 | `https://دامنه/in1` تا `https://دامنه/in20` |

## مراحل دیپلوی

### ۱. ریپازیتوری
سه فایل `Dockerfile`، `nginx.conf.template` و `start.sh` در ریشه ریپو قرار دارند.

### ۲. در Railway
1. **New Project → Deploy from GitHub repo** و همین ریپازیتوری را انتخاب کنید
2. Railway به‌طور خودکار `Dockerfile` را تشخیص و بیلد می‌کند
3. بعد از اتمام دیپلوی، به **Settings → Networking** بروید و **Generate Domain** بزنید

### ۳. ورود به پنل
پنل **فقط** با این مسیر باز می‌شود:
```
https://دامنه‌شما.up.railway.app/gucci/
```
یوزرنیم/پسورد پیش‌فرض 3x-ui را وارد کنید (admin/admin) و **حتماً بلافاصله از بخش تنظیمات تغییرش دهید**.

> 🔒 **حریم خصوصی:** اگر کسی فقط خودِ دامنه را باز کند (مثلاً `https://دامنه‌شما.up.railway.app`)، به‌جای پنل یک **صفحه کاملاً سیاه** می‌بیند. مسیر قبلی `/managepanel/` هم دیگر کار نمی‌کند. پنل روی **پورت داخلی 1** اجرا می‌شود و از بیرون دیده نمی‌شود.

## لینک سابسکریپشن (داینامیک — با هر دامنه‌ای که پنل باز شود)

سرویس سابسکریپشن به‌صورت خودکار فعال است و **ساختار لینک آن بین نسخه‌های مختلف 3x-ui ثابت و یکسان است**:
```
https://{دامنه‌ای که پنل با آن باز شده}/sub/{subId}
```
- لینک‌های ساب به‌صورت **داینامیک** ساخته می‌شوند: هر دامنه‌ای که پنل با آن بالا بیاید (دامنه Railway، دامنه اختصاصی شما، هر چیز دیگر)، لینک ساب هم دقیقاً با همان دامنه ساخته می‌شود — بدون هیچ تنظیم دستی.
- اگر روی سرور/VPS با پورت 2096 باز اجرا شود، همین لینک با فرمت دقیق `https://دامنه:2096/sub/{subId}` هم کار می‌کند (سرور دوم nginx روی پورت 2096 فقط ساب را سرو می‌کند و بقیه مسیرها سیاه هستند).
- **نکته Railway:** دامنه عمومی Railway فقط پورت 443 دارد؛ پس روی Railway فرمت بدون پورت (`https://دامنه/sub/...`) استفاده می‌شود.
- `subId` همان شناسه هر کاربر است که در دیتابیس ذخیره می‌شود؛ تا وقتی دیتابیس (Volume روی `/etc/x-ui`) حفظ شود، لینک ساب شما بعد از آپدیت/تغییر نسخه پنل هم ثابت می‌ماند و کار می‌کند.

## ساخت Inbound

در پنل، یک Inbound جدید بسازید با این تنظیمات دقیق:

| فیلد | مقدار |
|---|---|
| Protocol | VLESS |
| Listen Port | **8080** (این عدد نباید تغییر کند، چون nginx دقیقاً به همین پورت وصل است) |
| Listen IP | خالی یا `0.0.0.0` |
| Network | ws |
| Security | none |
| Path | هر مسیر دلخواه، مثلاً `/cdn` |

⚠️ اگر چند اینباند می‌خواهید، پورت‌های داخلی **8081 تا 8100** را با مسیرهای `/in1` تا `/in20` استفاده کنید (همگی از طریق `https://دامنه/inX` و TLS در دسترس‌اند).

### ساخت لینک کلاینت

```
vless://UUID@دامنه‌شما.up.railway.app:443?encryption=none&security=tls&sni=دامنه‌شما.up.railway.app&fp=chrome&type=ws&host=دامنه‌شما.up.railway.app&path=%2Fcdn#MyConfig
```

## مقاومت در برابر فیلترینگ — چه کارهایی انجام شده و چه کارهایی نمی‌شود

**انجام‌شده (بهترین روش‌ها):**
- ✅ همه‌چیز (پنل، ساب و اینباندها) فقط روی **443/TLS** و با ظاهر HTTPS عادی — تشخیص از روی ترافیک تقریباً ناممکن است
- ✅ پنل **مخفی** است: ریشه دامنه صفحه سیاه می‌دهد، پنل روی پورت غیرمعمول داخلی (1) است و مسیر قبلی حذف شده — اسکنرها پنل را پیدا نمی‌کنند
- ✅ `fp=chrome` در لینک‌ها (جلوگیری از شناسایی اثر انگشت TLS)
- ✅ ۲۰ مسیر اینباند جایگزین (`/in1` تا `/in20`) — اگر یک مسیر مسدود شد، سریعاً مسیر را عوض کنید
- ✅ سابسکریپشن با آدرس ثابت که به نسخه پنل وابسته نیست

**واقعیت مهم (صداقت کامل):** هیچ پروکسی‌ای در جهان نمی‌تواند **تضمین ۱۰۰٪** بدهد که «هیچ‌وقت فیلتر نمی‌شود». فیلترینگ به‌صورت پویا و کشوری است. آنچه می‌توان کرد همین موارد بالاست که احتمال شناسایی را به حداقل می‌رساند. اگر روزی مسیری بسته شد:
1. مسیر WebSocket را عوض کنید (بدون تغییر پورت)
2. یا از یکی از مسیرهای `/in1` تا `/in20` استفاده کنید
3. برای حداکثر مقاومت (VLESS+REALITY یا Hysteria2) به یک VPS با IP تمیز نیاز است — روی دامنه عمومی Railway امکان REALITY نیست چون TLS در لبه Railway تمام می‌شود

## Railway TCP Proxy (اختیاری)

اگر بخواهید یکی از اینباندها را به‌صورت **TCP خام** (بدون nginx) هم در دسترس بگذارید:
1. در Railway: **Networking → TCP Proxy → New TCP Proxy** بزنید و پورت داخلی را مثلاً `8080` انتخاب کنید
2. یک دامنه مثل `tcp://xxx.up.railway.app` و پورت می‌گیرید
3. لینک کلاینت: `vless://UUID@xxx.up.railway.app:پورت?encryption=none&security=none&type=tcp#TCP`

⚠️ توجه: ترافیک TCP خام بدون TLS **بسیار راحت‌تر** از VLESS+WS+TLS شناسایی می‌شود؛ برای مقاومت بالا از مسیرهای WebSocket روی 443 استفاده کنید.

## تست سریع

```bash
# پنل (فقط همین مسیر)
https://دامنه‌شما.up.railway.app/gucci/

# تست اینباند (باید Bad Request از Xray ببینید)
https://دامنه‌شما.up.railway.app/cdn

# تست ساب (با subId واقعی از پنل)
https://دامنه‌شما.up.railway.app/sub/{subId}
```

## نکات مهم

- دیتابیس/تنظیمات پنل (`/etc/x-ui`) روی فایل‌سیستم موقت کانتینر است. اگر می‌خواهید بعد از هر Redeploy تنظیمات (کاربران، Inbound ها، subId ها) پاک نشود، از بخش **Volumes** در Railway یک Volume به مسیر `/etc/x-ui` وصل کنید.
- اگر دامنه عمومی خودتان را در Railway تنظیم کنید (Custom Domain)، متغیر `RAILWAY_PUBLIC_DOMAIN` همان دامنه شما را می‌گیرد و لینک ساب خودکار درست می‌شود.
